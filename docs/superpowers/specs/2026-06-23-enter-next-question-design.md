# Enter 进入下一题设计

## 目标

答题界面已经显示作答结果或参考答案后，用户按 `Enter` 进入下一题；当前为最后一题时进入结果页。

## 交互规则

- 未判题的客观题：保留现有行为，有选项时按 `Enter` 提交答案。
- 已判题的客观题：按 `Enter` 进入下一题。
- 主观题完成“正确/错误”自评后：按 `Enter` 进入下一题。
- 点击“不会，查看答案”并显示答案后：按 `Enter` 进入下一题。
- 最后一题触发相同行为时：复用现有下一题流程进入结果页。
- 背题模式、弹窗打开、输入控件或可编辑区域聚焦时：不处理 `Enter`，避免误触。
- 答案尚未显示且不满足提交条件时：不处理 `Enter`。

## 实现设计

扩展现有 `src/keyboard-shortcuts.js` 键盘动作解析器：

1. 用独立上下文字段表示当前题是否已经显示结果或答案。
2. 当按键为 `Enter` 且结果已显示时，返回 `{ type: "next" }`。
3. 未显示结果时，继续按现有规则返回 `{ type: "submit" }` 或不处理。
4. 页面键盘处理器收到 `next` 动作后调用现有 `nextQuestion()`，不复制翻题、保存进度或结束测验逻辑。

## 状态判定

页面将以下任一状态视为“已显示结果或答案”：

- `hasSubmitted` 为真：客观题已提交，或用户点击“不会，查看答案”。
- `subjectiveStatus` 不再是 `pending`：主观题已经完成自评。

## 测试

- 保留并验证弹窗、背题模式和编辑区域的阻断行为。
- 页面集成测试确认 `next` 动作复用 `nextQuestion()`。
