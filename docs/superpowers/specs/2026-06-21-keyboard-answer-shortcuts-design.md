# 键盘答题快捷键设计

## 目标

为答题页面增加键盘操作：

- 按 `A`、`B`、`C`、`D` 选中或取消选中对应选项。
- 按 `Enter` 提交当前答案。
- 答案提交后，快捷键不再改变当前题，也不会自动进入下一题。

## 生效范围

快捷键仅在以下条件全部满足时生效：

- 当前处于答题页面。
- 当前不是背题模式。
- 当前题尚未提交。
- 页面没有需要优先处理键盘输入的弹窗。
- 焦点不在 `input`、`textarea`、`select` 或可编辑元素中。

## 按键行为

### A–D

- 按键不区分大小写。
- 仅选择题响应。
- 仅当当前题实际显示对应选项时响应。
- 调用现有 `selectOption` 逻辑，保持点击和键盘行为一致：
  - 多选题再次按同一字母会取消选中。
  - 单选题按字母会选中对应选项；若再次按下当前选项，则沿用现有点击行为。
- 辨析题和主观题不响应 A–D。

### Enter

- 客观题至少选择一个答案后才提交。
- 未选择答案时不执行任何操作。
- 主观题在文本输入区域中保留正常换行行为，不触发快捷提交。
- 已提交后再次按 Enter 不执行任何操作，不进入下一题。

## 实现方案

在 Vue 根组件中注册统一的 `keydown` 监听器，并在组件卸载时移除监听器。

监听器负责：

1. 判断当前页面状态、模式、提交状态、焦点元素和弹窗状态。
2. 将 A–D 映射到当前题实际存在的选项。
3. 复用现有 `selectOption` 和 `submitAnswer`，避免产生第二套答题状态逻辑。
4. 仅在快捷键确实被处理时调用 `preventDefault()`。

为便于自动化测试，按键判定和选项可用性判断应提取为独立、无副作用的辅助函数；Vue 监听器只负责读取当前状态并调用现有业务函数。

## 测试

自动化测试至少覆盖：

- 小写和大写 A–D 均可映射到对应选项。
- 非 A–D 字母不触发选择。
- 不存在的选项不触发选择。
- 输入框、文本框、下拉框和可编辑元素获得焦点时不处理快捷键。
- Enter 仅在允许提交且已有答案时触发提交。
- 已提交、背题模式、非答题页面或弹窗打开时不处理快捷键。

浏览器交互验证覆盖：

- 多选题可用 A–D 选中和取消。
- 单选题可用 A–D 选择。
- Enter 可提交已有答案。
- 提交后 Enter 不翻题。
- 在文本输入或弹窗中输入时不会误触发答题。

## 非目标

- 不增加 E、F 或其他选项快捷键。
- 不增加上一题、下一题快捷键。
- 不改变鼠标点击行为。
- 不改变提交后的导航逻辑。
